## 한 줄 요약

실시간 응급실 병상 정보에 재난문자와 이동 시간까지 따져 지금 갈 만한 응급실을 골라 주는 웹 서비스. 기획부터 데이터 수집, 추천 API, 지도 화면, 본선 발표까지 모두 담당

- **서비스** · 주변 응급실의 실시간 가용 병상 지도, 병상 혼잡도·재난문자·이동 시간을 따진 응급실 추천, TMAP 길안내 연결
- **담당** · 서비스 기획 · 병상·재난문자 수집 스케줄러 · 병원 자동 등록 · 추천 API · React 지도 화면 · 본선 발표
- **스택** · Java 21 · Spring Boot 3.5 · JPA · MySQL · Flyway · Caffeine · React · TypeScript
- **연동** · 국립중앙의료원 응급실 API · 행정안전부 재난문자 API · 카카오 로컬 · TMAP

## 구조

```text
NMC bed API ───── every 60s ──┐
Disaster SMS API ─ every 3m ──┼─▶ Scheduler ──▶ MySQL (hospitals · beds · alerts)
Kakao Local (new hospitals) ──┘                    │
                                                   ▼
Browser (React) ──▶ Recommendation API ──▶ TMAP route API
                         │                 (Caffeine cache · 1.5s fallback)
                         └─▶ RankingEvent log
```

## 추천 API가 따지는 것

1. 반경 안의 후보 병원 모으기
2. 정보가 1시간 넘게 지난 병원은 빼고 지도에 회색으로 표시, 5분이 넘은 병원은 감점
3. 재난문자 심각도가 BLOCK이면 후보에서 빼고, WARN이면 경고 배지만 표시
4. 응급실 가용 병상으로 병원별 혼잡 점수를 매기고 중환자실 여유로 보정
5. TMAP으로 차량·도보 이동 시간 계산
6. 혼잡 등급, 점수, 재난문자 심각도, 이동 시간 순으로 정렬해 상위 병원을 돌려주고, 계산 근거는 RankingEvent로 기록

## 트러블슈팅

<a id="encoding"></a>

### 1. 응급실 공공데이터가 들어오지 않던 문제 · PR #7, #8, #9

- **문제** 국립중앙의료원 응급실 병상 정보를 60초마다 받아 오게 했지만 데이터가 들어오지 않음
- **첫 시도** 인증키를 미리 인코딩하던 코드를 빼고 주소 전체를 마지막에 한 번만 인코딩. 응답이 JSON이 아니라 XML이라 파서도 바꿈. 그래도 그대로
- **원인 좁히기** 짐작을 멈추고, 같은 요청을 브라우저 주소 그대로, Spring WebClient, curl 방식, 공공데이터포털 자바 예제 네 가지로 보내 나란히 비교하는 디버그 API 작성
- **원인** 이미 인코딩한 주소를 WebClient에 넘기면 한 번 더 인코딩해서 한글 지역명이 두 번 인코딩됨
- **해결** 포털 예제처럼 파라미터마다 한 번만 인코딩. 의료원의 병원명과 카카오의 장소명이 서로 달라 별칭 매핑도 추가

<a id="cache"></a>

### 2. 캐시를 붙였는데도 잦던 TMAP 호출 · PR #16

- **문제** 추천할 때마다 후보 병원 최대 10곳의 이동 시간을 TMAP에 물음. 2분 캐시를 두었는데도 호출이 잦음
- **원인** 캐시 키에 후보 목록이 받은 순서 그대로 들어가, 같은 병원 조합도 순서가 다르면 새 요청으로 봄. 화면은 위치가 조금만 바뀌어도 전체를 다시 요청
- **해결** 후보를 병원 ID로 정렬해 캐시 키를 맞추고, 화면에서는 100m 안쪽으로 움직이면 다시 계산하지 않게 함
- **원래 있던 대비** TMAP이 실패하거나 1.5초 안에 답하지 않으면 직선거리로 이동 시간을 추정해 추천을 이어 감

## 기술 선택 이유

| 선택 | 이유 |
| :-- | :-- |
| 공공은 판단의 근거, 민간은 실효성 | 병상과 재난문자 같은 공공데이터로 갈 수 있는 병원을 거르고, 이동 시간은 민간 지도 API로 계산 |
| TMAP 요청은 서버를 거쳐서 | 지도 API 키가 브라우저에 드러나지 않게 |
| 기준값은 DB 설정 테이블에 | 탐색 반경이나 정보 유효 시간 같은 값을 운영 중에도 관리자 API로 바꿀 수 있게 |
| 추천마다 RankingEvent 기록 | 어떤 근거로 순위가 나왔는지 심사·감사·튜닝 때 다시 볼 수 있게 |
| Caffeine 캐시 | 같은 병원 조합의 경로 결과를 짧게 재사용해 TMAP 호출을 줄임 |
